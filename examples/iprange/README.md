# `iprange`: Minimal Shortest-Prefix FSMs for IP Ranges

`iprange` takes a list of labeled IPv4 (4-byte) or IPv6 (16-byte) address ranges
and builds a minimal deterministic finite-state machine (DFA) that classifies IP
addresses one byte at a time, in network (big-endian) byte order.

The state machine stops reading bytes as soon as the label is known. If
`10.0.0.0-10.255.255.255` maps to `private`, byte `10` transitions from the
start state to a terminal `private` state with no outgoing edges, without
reading the remaining three bytes.

---

## What It Is Useful For

`iprange` is built for precompiling large, sparse, overlapping sets of IPv4 and
IPv6 ranges (such as GeoIP tables, regional registry allocations, reputation
lists, or firewall rules) into a static classifier, including standalone C code
generated by `libfsm`. These datasets mix start/end spans that do not align to
CIDR masks with overlapping CIDR hierarchies (for example, city or customer
`/24`s carved out of regional `/8` or `/16` blocks, alongside fragmented
adjacent blocks for the same label).

Common IP lookup structures make trade-offs that fit poorly here:

- Flat lookup tables (`/16` or `/24` arrays) rely on IPv4 fitting in a 32-bit
  space. Across 128-bit IPv6 (or sparse datasets where populated ranges occupy
  scattered islands), flat tables blow up in memory, and multi-bit stride tables
  allocate mostly empty entries.
- Binary search or B-trees over start/end pairs handle sparsity, but each lookup
  does logarithmic 128-bit comparisons across pointer or array hops, and
  overlapping ranges have to be split or prioritized separately.
- Bitwise CIDR radix tries require power-of-two subnets, so one non-CIDR range
  can split into up to 62 CIDR subnets in 32-bit IPv4 (`31` peeled off the low
  end from `/32` up to `/2`, plus `31` off the high end, as in
  `0.0.0.1-255.255.255.254`) or 254 CIDR subnets in 128-bit IPv6. When CIDR
  blocks overlap, longest-prefix-match tries also have to track a fallback match
  at runtime while probing deeper branches that might miss.
- General FSM compilation (building an automaton per rule, then running subset
  determinization and Hopcroft minimization) handles byte ranges, but gets
  expensive across hundreds of thousands of rules and thousands of labels.

`iprange` resolves same-label overlaps up front and folds range decomposition
into automaton construction. Overlapping or adjacent ranges for the same label
merge into one span, and overlapping ranges with different labels are flagged
as conflicts. Each resulting range is walked like a base-256 odometer (emitting
at most 7 byte-range rules for IPv4 or 31 for IPv6) into an external register
array that tracks the open branch of the tree as it is built. Because a sorted
stream never backs up into an earlier byte prefix, finished states are memoized
as they leave the registers, producing a minimal DFA in one linear pass. At
runtime there is no longest-prefix backtracking or fallback state, and lookups
inspect 1 to 4 bytes for IPv4 or 1 to 16 bytes for IPv6.

## Usage

Input is a CSV stream of `start_ip,end_ip,label` lines:

```text
0.0.0.0,0.255.255.255,broadcast to current
1.0.0.0,9.255.255.255,internet
10.0.0.0,10.255.255.255,private
```

Build and run:

```sh
bmake -r
make -C examples/iprange
./examples/iprange/iprange -4 -f examples/iprange/v4ranges.csv -l dot
./examples/iprange/iprange -4 -f examples/iprange/v4ranges.csv -l c
./examples/iprange/iprange -6 -f examples/iprange/v6ranges.csv -l dot
```

### Flags

- `-4` / `-6`: Match IPv4 (4-byte) or IPv6 (16-byte) ranges.
- `-f <file>`: Read CSV lines from `<file>` (defaults to `stdin`).
- `-l <fmt>`: Output format (`c`, `dot`, or `fsm`).

## How the Algorithm Works

An IPv4 address in network byte order is a 4-byte big-endian unsigned integer
(and IPv6 is a 16-byte big-endian unsigned integer), so comparing two byte
arrays from left to right compares the two IP addresses numerically. Compilation
runs in three stages across `iprange.c` (interval cleanup and decomposition) and
`builder.c` (register-tracked tree construction and state memoization).

### Stage 1: Clean Up the Range Stream

Before building the machine, the input ranges are turned into a sorted,
non-overlapping stream where overlapping or back-to-back ranges with the same
label have been merged.

A linear pass first checks whether the list is sorted and free of cross-label
overlaps. Sorted exports take this path and merge touching same-label ranges in
place without sorting. If unsorted or cross-label overlapping ranges are
present, Stage 1 sorts per label to merge duplicates, re-sorts globally to
detect collisions, and reports each colliding label set with an example IP.

### Stage 2: Break Each Range into Shortest Byte-Prefix Rules

An IP range behaves like an odometer with 4 (or 16) wheels, each numbered `0`
through `255`. A start cursor begins at the start of the range and peels off
byte-aligned blocks until it reaches the end address.

When the cursor equals the end address, emit all 4 (or 16) bytes to the label's
leaf state and stop.

Otherwise, find the first byte where the cursor and the end address differ. If
the cursor has non-zero bytes to the right of that split point, it starts
partway through a block (like `1.0.1.0` inside `1.0.*.*`). Find its rightmost
non-zero byte, emit a rule from that byte value through `255`, reset that byte
to `0`, and carry `+1` to the left to reach the next `.0` boundary.

Once every byte of the cursor after the split point is `0`, the cursor sits at
the start of a block. If the end address runs to `255` in every trailing byte,
the remaining span is a single block: emit one rule for that byte range (or, if
that byte spans `0` through `255`, step one byte left to avoid testing
`0..255`) and stop. If the end address stops short of `255` in its trailing
bytes, every full block before the end address's partial block fits inside the
range: emit one rule for those blocks, advance the cursor to the `.0` start of
the end address's partial block, and repeat on the tail.

#### Example: `1.0.1.0 - 1.2.255.254`

| Step | Cursor | End | Situation | Emitted Rule | Covers |
| :--- | :--- | :--- | :--- | :--- | :--- |
| 1 | `1.0.1.0` | `1.2.255.254` | Cursor starts mid-block | `1.0.[1..255]` (3 bytes) | `1.0.1.0 - 1.0.255.255` |
| 2 | `1.1.0.0` | `1.2.255.254` | Cursor aligned, end stops early | `1.[1..1]` (2 bytes) | `1.1.0.0 - 1.1.255.255` |
| 3 | `1.2.0.0` | `1.2.255.254` | Cursor aligned, end stops early | `1.2.[0..254]` (3 bytes) | `1.2.0.0 - 1.2.254.255` |
| 4 | `1.2.255.0` | `1.2.255.254` | Cursor aligned, end reaches ceiling | `1.2.255.[0..254]` (4 bytes) | `1.2.255.0 - 1.2.255.254` |

### Stage 3: Build the Minimal DFA via `regs`

Rather than building a state machine per label and running NFA merging,
determinization, and minimization afterwards, `builder.c` builds the minimal
combined DFA as rules arrive.

A register array (`regs`, 4 slots for IPv4 or 16 for IPv6) holds the open
states along the active byte prefix across all labels. Each open register
records its outgoing transitions as a sorted list of byte ranges; when a new
byte range follows the previous one and points to the same target state, the
two fuse into one range.

When a byte in the prefix changes, deeper registers are finished (because the
input is sorted, no later range revisits that prefix). Finished registers are
popped from bottom to top and memoized in a hash table by their outgoing
transitions: if a matching state was built under an earlier prefix, its ID is
reused; otherwise it is stored once and linked to its parent register. After
the last range, the remaining registers close up to the start state and the
states and edges are written into a `libfsm` `struct fsm`.

## Why It Is Correct (and Minimal)

### 1. Why stopping on a short prefix is safe

A short prefix rule (such as `10` in one byte, or `1.0.[1..255]` in three
bytes) means every address starting with those bytes (from `.0` through `.255`)
belongs to that label.

One emitted rule is never a prefix of a longer rule. Across different labels,
that would mean addresses under the longer rule belonged to two labels, which
Stage 1 rejected. Within the same label, if the shorter prefix covers
`0..255`, any longer rule beneath it would be redundant, and Stage 2 does not
emit rules inside a covered block. Because no rule is a prefix of another,
nothing remains to decide once an accepting state is reached, so accepting
states have no outgoing edges.

### 2. Why merging ranges up front finds cross-range shortcuts

If an input splits `10.0.0.0-10.255.255.255` into two halves with the same
label, the concern is that decomposing individual ranges would miss the halves
combining into a 1-byte rule.

Every prefix rule covers a run of consecutive IP addresses. Stage 1 merges every
pair of same-label ranges that overlap or touch back-to-back, leaving at least
one unmatched or differently labeled IP address between any two remaining ranges
for that label. Consecutive addresses cannot cross a gap, so any valid prefix
block fits inside one merged range.

### 3. Why splitting a range leaves no gaps, extras, or wraparound

At the start of each loop step, everything before the cursor has been emitted
once, and the cursor is at or below the end address.

When the cursor begins mid-block, emitting from its rightmost non-zero byte
through `255` stays within the range because the cursor's byte at the split
point is smaller than the end address's byte there. Rolling that trailing byte
to `0` and carrying `+1` left moves the cursor to the next IP address. Even if
`255` bytes roll over to `0`, the carry stops at or before the split point
(where the cursor's byte was smaller than the end address's byte), so it cannot
wrap past the top of the address space or pass the end address.

When the cursor sits on a `.0` boundary and the end address stops partway
through its final block, the cursor's byte at the split point is smaller than
the end address's byte. At least one full block precedes the end address's
partial block (and the end address's split byte is at least `1`, so subtracting
one does not underflow). Emitting those blocks moves the cursor to the `.0`
start of the end address's partial block, at or below the end address.

When the cursor matches the end address, or sits on a `.0` boundary while the
end address runs to `.255`s, one rule covers the remaining span through the end
address and finishes. Each step picks up at the IP address after the previous
block, covering the range from start to end without gaps or extras.

### 4. Why any range takes at most 7 rules for IPv4 (or 31 for IPv6)

Each mid-block rounding step turns the rightmost non-zero byte into `0` and
carries left, zeroing at least one trailing byte per step. That happens at most
3 times for 4-byte IPv4 (or 15 times for 16-byte IPv6), and later steps leave
trailing zeroes intact.

From there, each full-block step matches at least one more leading byte to the
end address (at most another 3 steps for IPv4, or 15 for IPv6) before one final
rule finishes the remainder: at most `3 + 3 + 1 = 7` rules for IPv4, or
`15 + 15 + 1 = 31` for IPv6.

### 5. Why every emitted rule uses the fewest bytes possible

A rule would be a byte too long only if all 256 values (`0` through `255`) of
its final byte (and every address beneath them) fell inside the input range.

During mid-block rounding, the emitted byte range starts at `1` or higher.
Setting that byte to `0` subtracts one unit at that byte position, whereas
earlier rounding steps only added to bytes further right (less than one unit
here), placing the `.0` sibling below the range start.

During full-block steps where the end address stops short of `.255` in its
trailing bytes, extending that byte to `.255` runs past the end address.

On the final step, if the split byte covers `0` through `255`, the code steps
back one byte rather than testing `0..255` (it never needs to step back twice:
if the parent block had also been inside the range, rounding would have stopped
at that parent block's `.0` start and finished there). Otherwise either the
start byte is above `0` (so `.0` lies below the range start) or the end byte is
below `255` (so `.255` lies above the range end). When the loop finishes on a
single IP, either the input range was one IP or earlier steps left its last
byte at `0`, putting `.255` above the range end.

### 6. Why closing registers bottom-up builds the minimal DFA

Because the state machine has no loops, building the minimal DFA in a single
pass comes down to determinism, reachability, and merging states that accept
the same suffixes.

Each emitted rule covers addresses higher than every previous rule, and no rule
is a prefix of another. Where a new rule diverges from the previous one, its
byte range starts above the last byte on that register state, so outgoing
ranges are added in increasing order and do not overlap. Because rules arrive
in sorted order, once a leading byte advances, no later rule starts with the
old prefix, so freezing deeper registers cannot miss later transitions.

Leaf states are created only for labels referenced by an edge, and internal
states are created only with at least one path to a leaf, leaving no dead or
unreachable states.

Leaves have one state per surviving label, distinct labels cannot merge without
losing which label matched, and leaves accept while internal states do not.
Internal registers close from deepest byte to shallowest: when a parent
register closes, its child states already have memoized IDs, and adjacent bytes
sharing an ID have fused into one run. Two internal states therefore behave the
same on remaining bytes if and only if their run lists match, which the memo
table merges into one state. Finally, the start state cannot match a deeper
internal state: there are no cycles and every internal state reaches a leaf, so
walking from the start state to a deeper state and then feeding that deeper
state's longest accepted input gives a longer accepted input from the start
state.

## Complexity

For `M` input ranges, `W`-byte addresses (`4` for IPv4, `16` for IPv6, or `8W`
bits), and `V` states in the minimal byte-DFA:

| Approach | Build Time | Space | Lookup Time |
| :--- | :--- | :--- | :--- |
| `iprange` (sorted input) | `O(M * W)` | `O(M * W)` build buffer; `O(V)` DFA states | `1` to `W` byte steps (`<= 4` v4, `<= 16` v6), no backtracking |
| `iprange` (unsorted input) | `O(M log M * W)` | `O(M * W)` build buffer; `O(V)` DFA states | `1` to `W` byte steps, no backtracking |
| Binary search / B-tree on ranges | `O(M log M * W)` (after splitting overlaps) | `O(M * W)` interval endpoints | `O(log M * W)` comparisons |
| Bitwise CIDR longest-prefix trie | `O(M * W^2)` worst-case after CIDR split | Up to `16W - 2` CIDR prefixes per range (`62` v4, `254` v6) | Up to `8W` bit steps (or multi-bit strides) with fallback tracking |
| Flat `/16` or `/24` table | `O(2^16)` or `O(2^24)` | Fixed `2^16` or `2^24` entries (infeasible across 128-bit IPv6) | `O(1)` |
| Per-rule NFA + determinize + minimize | Subset construction + `O(256 * V log V)` | Peak NFA and unminimized DFA states; `O(V)` final | `1` to `W` byte steps |
